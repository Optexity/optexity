title: "Model Configuration"
description: "Choose the LLM your automations run on"

Run every LLM call in Optexity through [OpenRouter](https://openrouter.ai) with a single API key, and pick any model OpenRouter offers — Gemini, Claude, GPT, and more — without code changes.

## Environment Variables

| Variable | Type | Default | Description |
| --- | --- | --- | --- |
| `OPENROUTER_API_KEY` | `str` | Required | OpenRouter key used for every LLM call |
| `LLM_MODEL` | `str \| None` | `google/gemini-3.5-flash-lite` | Model for every LLM call that doesn't set its own |
| `LLM_MODEL_FALLBACK` | `str \| None` | `None` | Backup model used when a call fails |

```bash
OPENROUTER_API_KEY=YOUR_OPENROUTER_API_KEY
LLM_MODEL=anthropic/claude-sonnet-4.6
LLM_MODEL_FALLBACK=openai/gpt-5.6-terra
```

Get a key from the [OpenRouter dashboard](https://openrouter.ai/settings/keys).

## Model IDs

Use [OpenRouter model IDs](https://openrouter.ai/models) in `vendor/model` form:

| Model ID | Provider |
| --- | --- |
| `google/gemini-3.5-flash-lite` | Google (default) |
| `google/gemini-2.5-pro` | Google |
| `anthropic/claude-sonnet-4.6` | Anthropic |
| `openai/gpt-5.6-terra` | OpenAI |

Model strings saved in older automations, such as `gemini/gemini-2.5-pro`, keep working — they run as the matching OpenRouter model (`google/gemini-2.5-pro`). Update them to OpenRouter IDs when you next edit the automation.

## Setting a Model on an Action

Give one action a stronger or cheaper model than the rest of the automation with `llm_model_name`:

```json
{
  "type": "action_node",
  "extraction_action": {
    "llm": {
      "extraction_format": { "invoice_total": "str" },
      "extraction_instructions": "Read the invoice total from the summary table.",
      "llm_model_name": "google/gemini-2.5-pro"
    }
  }
}
```

| Action | Field |
| --- | --- |
| LLM extraction | `extraction_action.llm.llm_model_name` |
| PDF extraction | `extraction_action.pdf.llm_model_name` |
| Locator extraction | `extraction_action.locator.llm_model_name` |
| LLM query | `misc_action.llm_query.llm_model_name` |
| Dynamic form mapping | `dynamic_form_mapping_action.llm_model_name` |
| Captcha | `captcha_action.llm_model_name` |

Actions without `llm_model_name` use `LLM_MODEL`.

<Info>
  Captcha solving defaults to `google/gemini-2.5-pro` rather than `LLM_MODEL`, because captcha grids need a stronger vision model. Set `llm_model_name` on the `captcha_action` to change it.
</Info>

## Fallbacks

If a call fails — a timeout, rate limit, or provider outage — Optexity retries it and then switches to a backup model automatically, so a single provider's problems don't stop your automation.

Set `LLM_MODEL_FALLBACK` to choose the backup yourself. It backs up `LLM_MODEL` and any model set with `llm_model_name`, and can be from a different provider than the primary.

## Cost Tracking

Token usage and cost are reported per task, using the cost OpenRouter reports for each call. Reasoning tokens are counted inside completion tokens, so they're reported but never billed twice.

## Migrating from LiteLLM

Optexity no longer uses LiteLLM or provider API keys.

| Before | After |
| --- | --- |
| `LLM_MODEL_API_KEY`, `LLM_MODEL_FALLBACK_API_KEY` | Removed — set `OPENROUTER_API_KEY` |
| `GOOGLE_API_KEY` / `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` | No longer read |
| `LLM_MODEL=gemini/gemini-3.5-flash-lite` | `LLM_MODEL=google/gemini-3.5-flash-lite`, or leave it unset |
| `"llm_provider": "gemini", "llm_model_name": "gemini-2.5-flash"` | `"llm_model_name": "google/gemini-2.5-flash"` |

`llm_provider` is deprecated. Automations that still set it keep working, but new automations should put the full OpenRouter ID in `llm_model_name`.
